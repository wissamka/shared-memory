# Installation acceptance

Run these checks using harmless fictional content, then record results in `Automation/Schedule.md` or the log. Do not label unperformed tests as passed.

| Check | Observable result |
|---|---|
| Fresh setup | Vault opens; hub reaches profile, topics, source registry and procedures |
| Existing startup file | Original instructions remain byte-for-byte as a prefix |
| Repeat setup | Existing edited notes and source captures remain unchanged |
| Remember a preference | Current preference note and a source/session record are saved and readable |
| Fresh harness | Another session retrieves the preference and cites the same source |
| Correction | Prior preference is superseded, new preference is active, attribution retained |
| Conflict | Two inconsistent claims remain visible, with a specific unresolved question |
| Model attribution | Source model and synthesizing model stay distinct; unavailable IDs are explained |
| Daily review | Inputs produce useful sourced notes or reasoned no-change outcomes |
| Missed run | Older unreviewed captures and registered source days never collected during an outage are both recovered within authorized dates |
| Retry | Identical inputs do not create duplicate facts or captures; a stale overlapping manifest is rejected while exact completed-run replay remains valid |
| Partial failure | Failed/unreadable inputs stay pending; run does not claim complete coverage or label failure as no-change. Successful items checkpoint while explicit deferred items remain pending and can complete on a later same-day attempt |
| Import omissions | Unknown/mixed visible-content formats produce safe gaps; hidden/tool content never appears in captures |
| Integrity | Malformed pending files are identified and preserved; status does not count them as valid captured inputs |
| Additional harness | Connecting an existing vault preserves personal notes and unrelated startup text; real instruction loading is verified separately |
| Interrupted startup edit | The complete original or updated file survives; an ambiguous legacy partial block is preserved for review |
| Unavailable history | Review reports its source gap rather than inventing discussion contents |
| Chosen shared drive | Harmless note and reply survive a real second-device/connector round trip |
| Scheduler | Real task settings and next run are read back; manual test and observed scheduled run are distinguished |
| Forget | Authorized active/pending copies are addressed; direct capture and repeated import cannot recreate a suppressed source/session. Narrow-fact deletion and backups/external copies are handled explicitly |
| Optional archive | Accessible visible wording/order and legitimate repeats survive checkpoints; gaps and coverage stay explicit; hidden/internal material is absent |
| Voice calibration | Owner-authored messages stay distinct from assistant/quoted text; approved guide/examples drive a fresh sample without invented biography or a model-training claim |
| Readiness | Unconfigured sources, unobserved schedule, missing fresh recall and unverified cloud round trip remain unknown or incomplete even with zero pending captures |

Record evidence through [readiness](readiness.md) and the live log; archive/style checks follow [voice guidance](voice.md).

The automated package tests check file and bookkeeping behavior. The live agent must still evaluate synthesis quality, permission scope and whether another harness actually loaded instructions.
