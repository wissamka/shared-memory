# Installation acceptance

Run these checks using harmless fictional content, then record results in `Automation/Schedule.md` or the log. Do not label unperformed tests as passed.

| Check | Observable result |
|---|---|
| Fresh setup | Vault opens; hub reaches profile, topics, source registry and procedures |
| Existing startup file | Original instructions remain byte-for-byte as a prefix |
| Repeat setup | Existing edited notes and source captures remain unchanged |
| Remember a preference | Current preference note and a source/session record are saved and readable |
| Fresh harness | Another session retrieves the preference and cites the same source |
| Correction | Prior preference is superseded, new preference is active, attribution retained |
| Conflict | Two inconsistent claims remain visible, with a specific unresolved question |
| Model attribution | Source model and synthesizing model stay distinct; unavailable IDs are explained |
| Daily review | Inputs produce useful sourced notes or reasoned no-change outcomes |
| Missed run | Older unreviewed inputs are included, not lost at midnight |
| Retry | Identical inputs do not create duplicate facts or captures |
| Partial failure | Failed/unreadable inputs stay pending; run does not claim complete coverage |
| Unavailable history | Review reports its source gap rather than inventing discussion contents |
| Chosen shared drive | Harmless note and reply survive a real second-device/connector round trip |
| Scheduler | Real task settings and next run are read back; manual test and observed scheduled run are distinguished |
| Forget | Active and pending copies are addressed; limitations in backups/external histories are explained |

The automated package tests check file and bookkeeping behavior. The live agent must still evaluate synthesis quality, permission scope and whether another harness actually loaded instructions.
